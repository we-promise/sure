# Trade Republic native ingestion boundary

The native port contains restored-session readers, account/balance/position normalization and a connection-wide activity generation. It remains gated: `native_ready?` is false. `fetch_activities` still rejects per-account execution; the shared syncer uses `fetch_activity_group` to capture both timeline topics once. No legacy provider is switched over by these files.

The source behavior comes from `Provider::TradeRepublicClient`, `Provider::TradeRepublicSession`, `TradeRepublicItem::Importer`, and the three `TradeRepublicAccount` processors. The new reader reuses the WebSocket transport and protocol constants; it does not invoke the old sync method, importer or processors.

## Implemented boundary

`Provider::TradeRepublicClient::IngestionClient` accepts a trusted `credential_store` and optional injected transport settings. It exposes `get_account`, `get_cash`, `get_portfolio`, `get_price(instrument_id:, category_type:)`, `get_timeline_page(topic:, cursor:)`, and `get_event_detail(event_id:)`.

Each operation restores the encrypted `session_blob` through the credential store, refreshes the session, checks `/api/v2/auth/account`, and commits successful cookie updates before opening a WebSocket or returning data. It uses `persist_session_credentials!`, not the single-use refresh-token intent protocol: the existing implementation does not establish that ordinary Trade Republic cookies become unusable after every read. Network failures do not mark a harmless read as an uncertain consumed-token exchange. A failed cookie commit prevents further use of the returned cookie jar.

Pending login state and outstanding credential refresh intents block financial reads. Neither the phone number nor a PIN is needed to restore a session. The reader performs no QR initiation, login submission, challenge verification or polling. Those actions belong to the authorized connection lifecycle. The PIN must remain transient, as it is in the current `TradeRepublicItem`.

The reader accepts JSON and provider-domain Netscape cookie jars, including `#HttpOnly_` rows, validates header values, and never includes cookies, WAF tokens or response error text in financial evidence. An optional encrypted `waf_token` credential is supported. The existing global `TRADE_REPUBLIC_WAF_TOKEN` setting still requires a reviewed binding during migration; the new factory does not silently read it.

Responses parse money directly to `BigDecimal`, with collection, response-size, subscription-message and receive-time limits. A timeline call reads one topic page. A quote call tries the existing instrument-specific exchange order. A delta without a captured base is rejected. Transport exceptions expose stable error classes and safe messages. Native authenticated GETs explicitly set `max_retries: 0`, disabling the pinned [Net::HTTP 0.9.1](https://github.com/ruby/net-http/blob/v0.9.1/lib/net/http.rb) automatic GET retry. Retry decisions remain with the bounded activity-generation policy. A no-network regression exercises real HTTP startup and its request loop against a socket that times out, asserting one request and no credential commit or next session step; it remains unrun here.

HTTP 408 and actual HTTP/socket timeouts retain the timeout classification; HTTP 500, 502, 503 and 504 are explicitly transient. Other unclassified provider failures retain their existing nonretryable category. HTTP 429 carries a validated `Retry-After` delay, accepting bounded positive seconds or an HTTP date without retaining the raw header in errors. Sanitized rethrows preserve that delay. Malformed successful bodies and exhausted subscription-message limits remain malformed responses, rather than retryable timeouts.

## Identities and financial behavior

| Source | Native identity or behavior |
| --- | --- |
| Portfolio account | Exact `securitiesAccountNumber` for a new source; verified retained `portfolio` alias for an already copied source |
| Cash account | `cash:<securitiesAccountNumber>` for a new source; verified retained `cash` alias for an already copied source |
| Position | `trade_republic_position_<original remote portfolio number>_<ISIN>_<captured date>` |
| Timeline event | `trade_republic_event_<event ID>` |
| Security | Existing global ticker lookup using the ISIN, then create with the provider name; no alternate ticker or MIC is invented |
| Portfolio value | Sum of exact quantity times current price, excluding cash; a missing current quote preserves an existing reported total |
| Cash value | Available cash before cash, retaining the provider sign |
| Buy | Positive quantity, negative cash amount, canonical `Buy` label |
| Sell | Negative quantity, positive cash amount, canonical `Sell` label |
| Fees and taxes | Remain embedded in the provider cash amount and under `Trade.extra.trade_republic`; no additional fee entry |
| Cash movement | Category determines direction; CARD_CASH_BACK purchases receive the existing negative-provider-amount correction |
| Transfers | Preserve `funds_movement`, notes and the provider detail metadata |

Account inventory does not invent balances. Currency uses provider metadata, then the explicitly supplied item/family currency. Financial responses must match the requested securities account and currency. Unknown event categories stay unmapped; raw inputs remain available for later review. Malformed monetary values fail normalization instead of becoming zero. Only explicit `normalize_legacy_holding` and `normalize_legacy_activity` entrypoints convert identified historical monetary Floats through `BigDecimal(value.to_s)`.

Holdings retain average cost, daily external IDs and `delete_future_holdings: false`. The production factory now obtains prior quotes from `TradeRepublic::RetainedPortfolio` through the explicit frozen runtime collector. A prior quote can fill a missing current quote, with its original copy-run/mapping/checksum and `last_positions_sync` retained in encrypted evidence. It never supplies a current quantity or instrument list, never changes the quote's observation time, and cannot make the holdings snapshot authoritative. Missing current quotes make a holdings page incomplete and preserve an existing reported portfolio total. Current-day holdings pruning is deliberately withheld until the shared writer has the matching source-scoped policy.

Family locale is supplied explicitly for cash activity labels and trade display names. Canonical trade labels remain English, matching `Trade::ACTIVITY_LABELS`. Captured normalized records retain the resulting strings and timeline evidence includes the label snapshot. The holding observation day uses the captured family-local date; parity review must account for legacy jobs that used a different ambient `Date.current` zone.

## Retained account topology and quote inputs

The migration manifest uses legacy `kind` as the copied external identity. Those immutable `portfolio`/`cash` identities and their UUIDs are retained. A restored session's `securitiesAccountNumber` alone cannot replace either identity or authorize another portfolio. `RetainedPortfolio` verifies each original mapped account archive, its exact `trade_republic_account_id`, namespace, currency and copy-time financial binding, including unlinked accounts. The portfolio ID must be the remote number; the cash ID must be exactly `cash:<number>`. Both retained kinds, if present, must name the same owner. Discovery, balances and both timeline topics then translate only those proved remote identities onto their existing local aliases. Daily holding IDs keep the original remote number, preserving existing financial identity.

If a kind has no retained row, discovery emits a new canonical remote identity for that kind; it does not invent a historical alias or attach another financial account. An unlinked retained cash row stays unlinked, and its existence does not redirect portfolio cash events. A missing remote ID, incompatible portfolio/cash pair, duplicate source kind, mixed old/new duplicate portfolio, wrong namespace, post-copy financial relink or different restored-session owner requires explicit reconciliation. Neither the collector nor the factory changes a mapping, AccountProvider, financial Account or provider activation state to resolve it. Historical portfolio-to-cash financial relocation remains separate.

Factory construction reads verified archives once, with a 32 MiB cumulative archive bound, 1,000 source-account inventory bound and 10,000 cached positions per row. Duplicate cached ISINs, malformed/non-finite or negative historical prices fail instead of silently choosing one. Legacy Float quotes are converted explicitly via their decimal string; live responses retain the stricter exact-number contract. Cached quantities, completeness flags and timeline history do not become live inputs. The original encrypted archive remains the lossless copy; this collector projects only topology and quote values required by the reader.

`RuntimeContext` registers `trade_republic_retained_portfolio` explicitly. Runtime request/publication proofs pin its frozen output and recheck descriptor-only source, copied account binding and current status/currency inputs. They do not rescan raw positions for each quote request. Native checkpoint advancement does not replace this source baseline. New unlinked discovery may add a missing native sibling, while captured mappings and linked-account inventory remain pinned. Timeline continuation evidence also includes the frozen topology, so an in-progress generation cannot silently adopt another partition. Preexisting generations captured before this input contract need explicit abandonment/restart; no compatibility fallback guesses their topology.

## Implemented timeline barrier

`capture_timeline_page(topic:, cursor:)` returns an empty, incomplete `Page` whose encrypted evidence contains:

```text
topic: timelineTransactions | timelineActivityLog
request_cursor: original topic cursor or nil
response: { account, response: { items, cursors, ... }, next_cursor }
details: { event ID => original detail response }
```

This low-level convenience method still limits a single capture to 200 supported events. The production group path instead captures one raw topic page, followed by groups of at most 32 missing detail responses. `normalize_timeline_page(capture:, account:)` derives provisional activity records only after every selected event's detail has been captured. It never commits a checkpoint or authorizes absence pruning.

`TimelineGroups` and the shared `TransactionSync(resource: "activities")` implement the following protocol:

1. Capture original connection grant, committed cursor, source policies and exact account bindings. Each timeline group also pins observation time, timezone, currency, labels and cash/portfolio partition. The continuation is a digest of the original ordered capture prefix; source cursors/details remain in encrypted generation pages.
2. Fetch `timelineTransactions` completely before `timelineActivityLog`. Deduplicate connection-wide by explicit event ID, first occurrence winning in topic/page/item order. Distinct IDs with equal financial values remain distinct. A duplicate claiming incompatible cash/securities destinations fails instead of producing two ledger legs. Missing IDs fail.
3. Stage raw pages and bounded detail slices before fanout. Every required detail must exist. Repeated upstream cursors, malformed ownership, response limits or failed details cannot declare completion. Both topics must reach their actual terminal page; an empty complete timeline still produces both account children.
4. After four response groups, defer the same logical Sync. Rebuild from its exact generation pages and resume the next topic/detail slice. A different Sync cannot adopt an unfinished activity generation. Page order/count, generation ID, byte limits and digest are verified before using the prefix. No latest-snapshot lookup or large cursor payload is used.
5. Seal all account children only after the terminal group. The shared writer preserves original source-policy/link revisions; unlinked accounts receive retained activity observations. Resolve securities before entering the child financial transaction. Replay skips successfully applied children, and the connection checkpoint advances only after every child succeeds. Activities do not set a holdings checkpoint or authorize holdings absence.
6. Commit an immutable credential receipt in the same transaction as each confirmed session-cookie rotation. Receipts pin the original Sync, generation, next page, preceding captured page and input fingerprints; issuance and every subsequent credential read require the current lease and writer epoch. Captured groups name their exact receipts. Receipts left by a failed request can bridge only credential revisions for that same missing page, which must still be fetched and captured. Source/configuration/authorization changes fail. A rebuilt factory may recapture its execution clock with all other input fingerprints unchanged. Plaid keeps its existing transaction folding, restart and strict direct-token grant checks.

The current connection checkpoint is an opaque digest referencing the completed generation, **not an imported legacy newest-event shortcut**. Each new generation scans both topics from their beginning. This avoids skipping history that has not been retained or published. Incremental newest-ID stopping and adoption of historical merged caches remain separate migration work. The legacy importer intentionally full-fetches when its newest ID survives but portfolio history is empty; no native shortcut bypasses that recovery invariant.

Bounds are 50 upstream pages per topic, 5,000 raw events per generation, 32 details per response group, 8 MiB per typed source/detail capture, 500 total generation groups and 64 MiB decoded / 96 MiB stored generation input. The detail bound is checked while accumulating responses, and total decoded bytes before batch insertion. Reaching any bound fails without promoting the checkpoint. These are acceptance limits, not permission to silently truncate old history. Repeated decoding/fingerprinting of the bounded prefix and per-operation authentication require performance verification against realistic histories and lease duration.

Migration `20260915190000_allow_connection_activity_generations.rb` extends generation/role/checkpoint constraints and adds composite stream foreign keys so activity children cannot reference transaction generations. Existing transaction batches are backfilled with their captured resource. Rollback refuses while retained activity generations exist; their disposition must be explicit. This migration has not been executed, and `schema.rb` is unchanged.

Migration `20260915200000_create_provider_credential_receipts.rb` adds encrypted receipt fingerprints, exact connection/generation/Sync foreign keys and database guards for activity-only scope, preceding-page ownership and immutable updates. It has not been executed. Recovery permits at most 256 receipts for one page and issuance permits 32,000 per generation, with at most 64 rotations in one request group and 4 KiB of stored evidence per receipt. Missing, foreign or discontinuous receipts fail closed. Receipts prove confirmed ordinary session rotations only; they cannot resolve an uncertain single-use credential refresh. Normal receipt destruction is refused, and there is no automatic purge. Administrative deletion invalidates any replay that needs the removed proof. Migration-created database guards and their behavioral tests are required before acceptance; the unchanged Ruby schema does not install these triggers.

An explicit adapter retry policy now converts classified activity transport failures into same-Sync deferrals. Trade Republic admits only `TransientProviderError`, `Timeout` and `RateLimited`, after rechecking the live lease, exact request position and credential receipt chain. It permits five transport retries per generation at 15, 30, 60, 120 and 240 seconds. A supplied valid `Retry-After` can extend the delay to at most 300 seconds; malformed or longer supplied delays decline automatic retry rather than running before the server permits it. The durable `transport_retry_count` does not reset after successful pages and is independent of ordinary page-budget deferrals. Migration `20260915220000_add_provider_generation_transport_retries.rb` supplies that counter and its database bounds; it remains unexecuted. The default adapter policy declines retries, and Plaid's transaction path never enters it.

The old split-account cleanup deletes only portfolio cash transactions whose event IDs are present in the cash snapshot. It is not authorization to delete unrelated portfolio transactions, protected records or records owned by another source. An incremental migration must backfill source evidence for those legacy entries before considering relocation or cleanup.

## Remaining activation acceptance

Session/login jobs, polling endpoints and legacy sync consumers must share the same credential ownership/serialization protocol. Reauthorization must pin the same provider identity or explicitly create a replacement connection. Browser/WAF configuration needs an explicit credential binding. Production quote batching and request budgets need verification: the bounded reader currently authenticates each operation, which favors isolation but adds round trips for large portfolios.

Clean continuation and sealed-child replay use captured detail, label and link-partition inputs without refetching completed responses. Confirmed cookie commits that precede a failed or uncaptured response now have durable receipt proof. An explicit retry of the same Sync validates those receipts against the fresh factory grant before the next request; its already applied discovery checkpoint is reused even if the retry counter is still zero. Receipt recovery never supplies a missing HTTP response, advances a cursor or completes a financial child.

Classified activity transport failures now use the existing delayed Sync job path before terminal failure; focused full-job tests retain the same Sync and generation and replay only the missing request. Authentication/reauthorization, malformed responses, explicit capture limits, unclassified `ProviderUnavailable`, retry exhaustion and failures outside activity fetches remain errors. Ownership failures cannot schedule a transport retry or settle a replacement worker. A worker killed before scheduling its deferral now has a separate [execution-recovery protocol](provider-sync-continuations.md#interrupted-executions-and-finalization); its exact lease, original Sync and credential chain must survive admission. That implementation and its acceptance tests remain unverified. Completed generations require their explicitly named receipt proof; an unrelated credential update cannot be adopted. Each credential read also checks the live lease, including when the cookie jar did not change; a request already in flight when the lease expires cannot publish a stale response.

Historical timeline reprocessing and portfolio-to-cash relocation remain open. Copied account topology and cached quote handoff are implemented but unrun; the original typed archives still contain the complete copied positions and timeline payloads. The legacy merged timeline updates matching IDs and keeps the latest 5,000 events; full native scans and retained generation evidence do not themselves prove safe reprocessing or relocation of existing financial entries. Unlinked native observations are retained, and full scans can rediscover them after linking, but efficient retained-history replay remains to be implemented. Shared current-day holdings reconciliation must be source scoped and permitted only after every captured position imports successfully. Review malformed money, Netscape HttpOnly cookies, localized decimal parsing and captured dates as explicit parity decisions.

Focused Minitest coverage is written for normalization, source isolation, cookie commit ordering, exact monetary parsing, bounded topic/detail continuation, duplicate routing, byte limits, generation fanout, failed-child replay, deferred scheduling and admitted rotation chains. Real-copy retained-portfolio tests exercise factory discovery and dual-topic routing onto unchanged copied IDs, quote provenance and incomplete coverage, absent/unlinked siblings, unresolved remote identities, missing archives, post-copy relinking, foreign inputs and descriptor-only replay. Receipt tests cover atomic cookie rollback, uncaptured-response recovery, exact discovery reuse, missing/foreign proof, expired-lease denial, database ownership and immutable updates. Full-job transport tests cover scheduled receipt recovery, retry exhaustion, independent pagination budgets, terminal error exclusions, server delays and Plaid isolation. Shared group tests cover backward-compatible transaction decoding and activity retention; existing Plaid generation tests remain required regression coverage. None have been executed in this workspace because Ruby is unavailable. Existing Trade Republic behavior remains active until the migration-created database constraints, tests, job recovery and end-to-end migration acceptance pass.
