## Summary
- add `FamilyMembership` as the first compatibility layer for multi-ledger support
- store the active ledger in `Session.data` and resolve `Current.family` from session context
- add a user-menu ledger switcher plus controller/model tests for the phase-1 skeleton
- add a detailed execution and acceptance plan in `docs/plans/multi-ledger-phase1.md`

## Recent Updates
- Refactored the ledger switcher into a sleek, purely text-based Workspace Switcher (Popover) in the left sidebar (similar to Notion workspace switcher) to fix Windows icon-loading issues and provide a better UX.
- Added `FamiliesController#new` and `#create` to allow users to create new ledgers directly from the UI.
- Automatically assigns the creator to the new ledger via `FamilyMembership` and switches their session context.
- Fixed a bug where creating a new account (e.g., Asset/Liability) under a secondary ledger would crash due to strict `User#family_id` validation. The validation now correctly respects `FamilyMembership` for multi-ledger users.
- Fixed the base currency dropdown in the "New Ledger" modal to display correctly formatted currency names instead of Ruby memory references.
- All new UI elements are fully internationalized (`zh-CN` and `en`).

## Scope of this PR
This is intentionally **phase 1 only** for issue #1696.

Included here:
- membership table + backfill migration
- session-scoped active ledger ID
- compatibility resolver methods on `Current`, `Session`, and `User`
- minimal ledger switcher in the user menu
- focused tests for the new session/current/user behavior
- UI for ledger creation and switching

Explicitly **not** included here:
- full invitation flow rewrite
- multi-ledger role / permission redesign
- settings/profile page redesign for managing multiple ledgers
- full audit of every controller/view/job across the app
